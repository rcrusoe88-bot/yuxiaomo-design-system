# 扩展指南 · 如何往里加东西

> 这套系统会长期生长：新品牌主题、新组件、新版式、新模板、新设计元素。
> 本文定义**五类扩展的统一作业流程**——每条都有「放哪 / 怎么命名 / 必须补什么 / 什么算完成」。
> 目的只有一个：**新增的东西能被 Agent 发现并使用**。放进仓库 ≠ 进了系统；没进索引、没进文档的产出，对 Agent 等于不存在。

## 零、四条铁律（适用于所有扩展）

| # | 铁律 | 说明 |
|---|---|---|
| L1 | **只加不改语义**（additive-first） | 新增能力一律"加"：加组件、加主题、加模板。修改既有组件/令牌的**语义或默认值**属于破坏性变更，需记一行变更说明 + bump 次版本号，并检查 `examples/` 所有样例是否仍成立。 |
| L2 | **可见性 = 登记**（registry） | 任何新增都必须登记进对应目录的 `README.md` 索引表。索引是 Agent 的发现入口，不是给人看的门面。 |
| L3 | **可复用优先于能用**（no one-off） | 只服务一页的东西不叫组件，叫页面内容。要进 `src/lib/` 就必须能被第二个项目复用；否则留在 demo 里。 |
| L4 | **有证据**（evidence） | 新增的**审美规则**必须写清"从哪来 / 为什么有效"。来源可以是参考手册逆向（标页码）或真实项目迭代（标项目名），但不接受"我觉得好看"。 |

## 一、五类扩展速查

| 类型 | 放哪 | 命名 | 完成后必须 |
|---|---|---|---|
| **E1 品牌主题** | `src/lib/themes.js` | key 用品牌小写（`yuantai`） | 补 `references/tokens.md` 主题表 + `README.md` 主题表；跑一遍 `examples/` 确认对比度 |
| **E2 React 组件** | `src/lib/<族>.jsx`（族见 `components.md`） | PascalCase 且语义化（`TierCards`，不是 `Box3`） | 导出到 `src/lib/index.js` + 补 `references/components.md` 的 API 表 + 在 demo 里真实用一次 |
| **E3 版式原型** | `references/layouts.md` | `L9 / L10…` 顺延编号 | 写清"何时用 / 由哪些组件构成 / 密度等级"，并补进叙事铁律 |
| **E4 参考模板** | `templates/` | `tpl-<场景>-<版式>.html` | 补 `templates/README.md` 索引 + 一张预览图 + 写明页数/主题/适用场景 |
| **E5 设计元素** | `elements/` | `el-<族>-<名称>.svg` | 补 `elements/README.md` 母题登记表 + 说明换色方式（须吃主题令牌） |
| **E6 语料（手册逆向）** | 参考手册库（仓库外） | — | 用《手册设计元素提炼提示词》逆向，产出并入 `references/rules.md`（新规则）或作为新组件候选 |

> **E6 的产物不直接进本仓库**：逆向文档留在本地参考库，只有被验证、被抽象成"规则 / 组件 / 令牌"的部分才进系统。这样仓库里永远是设计决策，而不是别人的手册抄本。

## 二、各类扩展的细则

### E1 品牌主题

一套主题 = **7 个角色 + 1 条时间轴色带**：
`functional`（主色 / 表头 / 高亮）、`header`（主色深档）、`dark`（结构页深底）、`tint`（浅底）、`zebra`（斑马纹）、`capsuleLight`（浅胶囊）、`capsuleDeep`（炭胶囊）、`ramp`（4 档递变）。

- **对比度自查**：`dark` 上放白字、`functional` 上放白字、`tint` 上放深字。三者任一不成立就改值，别靠加阴影救。
- **一册一色相**（R1）：8 个值必须同族；允许"主色 + 中性深灰"这一种组合（远泰红即此例）。
- **已知坑**：`TierMatrixTable` 列头取 `[capsuleLight, header, functional, capsuleDeep]`。若 `header` 与 `functional` 同值，两个档位会撞色、递进感消失。新主题若用该表，请给 `header` 设独立的中档色。

### E2 React 组件

- 组件只吃**令牌**，不写死色值；换主题必须自动生效（`theme` 从 `ThemeProvider` 取或显式传入，受控优先）。
- **一个组件一种视觉职责**。若发现自己在同一组件里写 `variantA / variantB` 两条完全不同的结构，那应该是两个组件。
- 新增后跑：`node shot.cjs` 目检 + `node export-pdf.cjs` 确认不破 A4 分页。

### E3 版式原型

原型 = "页面的句型"。新增时回答四问：
① 它承担叙事的哪一环（建立信任 / 讲能力 / 促成行动）？② 由哪几个组件构成？③ 密度等级（疏 / 中 / 密）？④ 与它相邻的页该是什么密度才不累？

### E4 参考模板

- 模板是**可直接套用的一整页**（不是组件片段）：独立 HTML、双击即开、A4 尺寸正确、打印色正常。
- 模板里只放**结构 + 占位文案**，不放任何公司的真实数据与 LOGO——品牌素材走 `assets/<brand>/` 注入。
- 模板内不写死色值，用 CSS 变量承接主题令牌，保证"换主题即复用"。

### E5 设计元素

- 设计元素 = 与品牌无关、可跨主题复用的装饰 / 图形单元（几何母题、纹理、分隔件、标记）。
- 硬性要求：**矢量（SVG）**、**单色或吃令牌变量**、**无位图**、**无 emoji**；并注明"允许出现在哪些页型"。
- 当前设计语言只允许**三个装饰母题**（胶囊棒 / 签名角 / 色带，见 `../design-language.md`）。**新增母题要慎**——母题越多越像模板堆砌，与「克制即高级」直接冲突。加之前先问：现有三个母题真的表达不了吗？

## 三、什么能进 public 仓库

本仓库是公开的，红线如下：

| 可以进 | 不可以进 |
|---|---|
| 通用设计规则、令牌、组件代码 | 客户 / 雇主的**保密素材**（未公开产品数据、内部实验图、未发布文案） |
| 自有或已授权的品牌素材（LOGO、实景图） | 第三方手册的**原始文件与逐页截图**（逆向结论可以，原图不行） |
| 逆向得出的**抽象结论**（规则 / 色值 / 版式） | 带客户名的完整项目手册成品（除非已公开发布） |
| 公版字体名与字体栈 | 商业字体文件 |

拿不准时：素材放本地 `assets-local/`（已在 `.gitignore`），只把"能公开的设计结论"推到本仓库。

## 四、完成定义（DoD）

一次扩展算"完成"，当且仅当：

- [ ] 文件已落地到正确目录，命名符合规范
- [ ] 已登记进对应索引（`templates/README.md` / `elements/README.md` / `references/components.md` / `references/tokens.md`）
- [ ] 若引入新的审美规则或反模式，已写进 `references/rules.md` 或 `anti-patterns.md`，并附证据
- [ ] 在 demo 或 examples 里**真实使用过一次**（没被用过的组件等于没验证过）
- [ ] `node export-pdf.cjs` 通过，A4 分页与打印色正常
- [ ] 未破坏既有样例（additive-first）
