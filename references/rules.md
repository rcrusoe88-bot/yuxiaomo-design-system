# 22 条可命名审美规则

> 每条规则都有名字、一句话定义、实现它的组件、以及原始证据页。设计时逐条对照；评审时直接点名（"这条违反 R5"）。
> R1–R13 源自 GenScript 三册；R14–R21 源自 MCE 五册（`行业参考手册库/MCE_皓元/设计元素完整清单_MCE.md`）；R22 源自 MCE 11 页版式细读的 v0.4 组件补齐。

| # | 规则名 | 一句话 | 对应组件 | 证据 |
|---|---|---|---|---|
| **R1** | 一册一色相 | 每本手册/每章只用一个色相家族，功能色+表头色+浅底+深底全在族内，永不引入第二色相 | `ThemeProvider` | 三册全页采样 |
| **R2** | 深底只属于结构页 | 满版深色只允许封面、章节页、封底；内页永远白纸 + ≤10% 主题色实底点缀 | `Cover` / `SectionDivider` / `BackCover` | NA p1/p8、CE p1/p12、PA p1/p3/p24 |
| **R3** | 45°胶囊棒是品牌签名 | 结构页装饰 = 多档同色全圆角长条 45° 斜穿出血，白+浅+主+深四档叠加、100% 不透明平涂、无渐变、**等距平行** | `CapsuleDecor` | 全部封面封底 |
| **R4** | 页题是胶囊、节题是色字 | 页级标题 = 实底 stadium 全圆胶囊白字居中；小节标题 = 主题色粗体字居中，两级标题一"面"一"字" | `PillTitle` / `H2` | 三册所有内容页 |
| **R5** | 表头实底、表体无竖线 | 表头主题色实底+白字+列间白缝+顶部圆角；表体只有 0.5pt 横线 + 极浅斑马纹；首列可合并加粗 | `SpecTable` | 三册全部表格 |
| **R6** | 右上大圆角签名角 | 卡片/流程容器/引文面板的圆角集中在**右上角**（半径≈其余角 3~4 倍），全稿统一方向 | `StatCardRow` / `FlowChain` / `IconFlowBar` / `TestimonialCard` | CE p2/p6、PA p4、NA p3/p7 |
| **R7** | 卖点用卡、证据用表、证明用原图 | 数字承诺放浅色圆角卡；参数放实底表头表；实验证据保留仪器原始图（直角、无框、无阴影、无滤镜） | `StatCardRow` / `SpecTable` / `EvidenceGrid` | CE p4-5、NA p5-6 |
| **R8** | 承诺数字必高亮 | 交付周期/产能/效率等关键数字用主题色加粗，其余表格文字保持灰色 Regular | `SpecTable`(`highlight`) / `DataChart` | PA p5、CE p8 |
| **R9** | 流程下面必跟时间轴 | 定性流程图下方加按时长比例分段的色带（浅→深递进）+ 通栏箭头 + 黑粗"N 周起" | `FlowChain` + `TimelineBar` | CE p8/p10、PA p19/p22、NA p3 |
| **R10** | 案例固定三段式 + 横幅收口 | "挑战→解决方案→结果"字段骨架，结尾一条浅色通栏胶囊横幅给一句带数字的结论 | `CaseBlock` + `ConclusionBanner` | PA p9/p17/p20、CE p4-5 |
| **R11** | 章节闭环即留白 | 一个服务单元讲完必留下半页空白再开新章；密度曲线"带→卡→表→案例→空白"循环 | `Page`（留白） | CE p3/p7/p10下半页、PA p8 |
| **R12** | 图标面性、插画署名、照片零出现 | UI 图标一律单色面性填充；科研插画全彩并保留署名行；全稿 0 张照片 | `Icon` / `EvidenceGrid` | 三册全稿 |
| **R13** | 零阴影零渐变零描边装饰 | 高级感全部来自同色相的明度阶梯，不用阴影/纹理/半透明叠加 | 全局 | 三册全稿采样 |

## 第二批：来自 MCE（皓元）五册的 8 条新增规则

> 这批规则补的是本系统原本的**短板**：流程拓扑的语义分工、技术数据的呈现语体、服务型手册的信任与转化结构。

| # | 规则名 | 一句话 | 对应组件 | 证据 |
|---|---|---|---|---|
| **R14** | 一站一拓扑 | 流程用链、收敛用漏斗、迭代用环、组合用公式 —— 不同语义配不同拓扑，**绝不复用一种图凑数** | `StagePipelineChain` / `FunnelStages` / `CycleFlowDiagram` / `ComboEquationDiagram` | service p03–p06 |
| **R15** | 深浅=顺序，色相=并列 | 表达时间/成熟度的递进用**同色系深浅**；表达并列分类用**异色相**。两者不可互换 | `FunnelBand`（待补）/ `StagePipelineChain(spectrum)` / `CategoryTagRow` | library p03（`#5BC7DF→#B6E6F1` 四段递进）、p44（7 色相并列） |

| **R18** | 量化承诺内联加粗 | 产能/合规/周期等数字作为**加粗文字嵌在叙述里**，而不是做成独立统计块 | `Lead`（行内 `<b>`）/ `InlineStat` 用法 | service p03/p06（400+ 台 / 1,100+ 方法 / 50 万+次） |
| **R19** | 信任靠同行评议，不靠 logo 墙 | 用期刊封面墙 + 编号引用建立可信度，期刊名加粗做视觉锚点 | `CitationBlock` / `MediaCoverGrid`（待补） | service p02（右缘期刊墙 + 18 条引用） |
| **R20** | 深色收尾转化 | 封底用深色**反转**全册浅底，集中放联系方式 + 二维码 + 品牌口号，让"行动区"视觉重量最重 | `BackCover` / `ContactFooterBand`（待补） | service p08、qms p01 |

## 第三批：来自 v0.4 组件补齐的 1 条新增规则

> 这批规则的来源不是新手册，而是**在把组件补齐到 71 个的过程中暴露出的选择风险**：
> 一旦组件支持"多档配色"，默认值选错就会让整册变花。

| # | 规则名 | 一句话 | 对应组件 | 证据 |
|---|---|---|---|---|
| **R22** | 类目色纪律 | 组件的多档配色**默认同色相**（`palette="tone"`，`toneRamp`）；只有当颜色本身承载类目含义时才允许跨色相（`palette="category"`），且必须经 R21 全册锁定 | `HexChain` / `ProductCardGrid` / `NumberedStepFlow` / `CategoryTagRow`（`palette` 参数） | MCE library p44 七色相并列（确有类目含义）vs p06/p40 同色相多档（仅"第一项、第二项"） |

### 三条被 MCE 验证、但**我们主动不采纳**的做法

| MCE 做法 | 我们为何不采纳 |
|---|---|
| 中英双语标题成对（中文实标题 + 英文幽灵镜像叠压） | 你已明确要求**去除主标题下英文副标题**。该手法保留为 `GhostPairTitle` 的**可选变体**，不设为默认（见队列 P1） |
| 玻璃拟态半透明面板（生化试剂海报） | 已在 `anti-patterns.md` 列为黑名单：它是 AI slop 的高频特征，且在印刷 PDF 上极易翻车 |
| 分子彩纸作为第 4 个装饰母题 | `design-language.md` 规定**只有三个母题**。母题扩散是"模板堆砌感"的来源；如确需，只作为 `CapsuleDecor` 的一个 preset，不新增母题 |

## 使用提醒

- **R2 + R4 + R5** 是辨识度最强的三条，违反任一条，稿子立刻"不像这套系统"。
- **R6 的方向必须全稿一致**（都是右上角），方向混用会显得随手贴的。
- **R3 的"等距平行"是硬要求**：胶囊棒必须由 `d = x − y` 等距参数生成（见 `CapsuleDecor`），不可随手摆几根——"稀疏、随意"正是最常见的翻车点。
- **R9 不可拆**：只画流程不给时间轴，等于只承诺"有这一步"却不承诺"多久"——B2B 读者要的恰恰是后者。
- **R22 是默认值的规则**：多档配色组件（`HexChain` / `ProductCardGrid` / `NumberedStepFlow` …）**不传 `palette` 就是 `tone`**。若想跨色相，请先回答："这些颜色**各自代表一个类目**吗？" 答不上来就别跨——跨色相而没有语义，是"花"而不是"丰富"。
